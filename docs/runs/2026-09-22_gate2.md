## 1. What this gate answers

Spec §10.3 Gate 2:

> Is projection geometrically plausible?  
> **`ρ_l` after T1 not already ≈ 1 on most registry layers.**

`ρ_l = k_l / d_l`, where `k_l` is the number of leading input directions that hold a fraction ε of
layer `l`'s input energy on Task 1 (§7.2). If Task 1 already fills a layer's input space, hard
projection (GPM) leaves that layer no free directions. A GPM/SGP comparison would then measure
frozen layers rather than protected ones.

The spec does not say what "≈ 1" or "most" mean. The following was decided before the run and is
recorded in `flowcl/analysis/gates.py`:

| Choice | Value |
|---|---|
| ε for the verdict | 0.95 (the §7.2 default); 0.90 and 0.99 are evidence only |
| "≈ 1" | `ρ_l ≥ 0.90` |
| "most" | a **strict** majority: the gate fails if > 50% of the 91 registry layers are saturated. Exactly 50% passes |
| Verdict checkpoint | Gate 1 `seq_ft` stage 0, i.e. exactly the Task-1 state that GPM would protect |

## 4. Structure in the numbers

**Trunk: moderate occupancy, rising with depth.** The median ρ @0.95 per trunk block is 0.335, 0.349,
0.371, 0.401, 0.434, 0.454, 0.475 and 0.488 for blocks 0 to 7. MLP `fc2` inputs (the post-GELU hidden
layer, d = 2048) are the fullest trunk layers: median 0.626 against 0.425 for `fc1`. They are also the
only layers that approach saturation at ε = 0.99.

**Decoder: very low occupancy.** Action-position layers hold 95% of their input energy in about 10–30
directions out of 512 or 2048. Occupancy rises slightly with depth (median of self-attn and MLP per
block: 0.023, 0.032, 0.043, 0.053). The low values are energy concentration, not rank deficiency:
every decoder layer's Gram is numerically full rank (`numerical_rank = d_in`). The data has all
directions; almost all the energy lies in a few of them.

A plausible reason, *not tested here*: decoder tokens are built from a 7-D noisy action
(`action_in`), 16 learned chunk positions, and AdaLN modulation by a scalar `s`. That is a small
number of degrees of freedom per token, compared with the trunk's 229 tokens of image, language and
state.

**Small-d input layers** (`trunk_input`, `decoder_input`) are counted in the verdict but flagged
`small_d` in the JSON. Their ρ moves in steps of 1/8 or 1/7, and at d = 7 there is nothing to
protect. They do not change the verdict: removing both would give 0 of 89 saturated.

## 5. What passing does *not* imply

Gate 2 asks only whether Task 1 leaves free directions. It does. The decoder result cuts both ways,
and Gate 3 must separate the two readings:

1. **Cheap protection.** GPM can protect the decoder's Task-1 subspace (a few percent of each layer)
   and leave most of the input space free for later tasks.
2. **Blocked plasticity.** If the decoder's dominant directions reflect what an action chunk *is*
   (chunk position, noise scale, `s`) rather than which task is running, later tasks' decoder inputs
   will lie in the **same** few directions. Their gradients will then fall almost entirely into the
   protected subspace (`c_l ≈ 1`), and hard projection will suppress learning in exactly the layers
   that fit the velocity field.

`seq_hetero`'s curriculum YAML predicts "low `c_l`", but that prediction was made at the task level,
not per layer. Treat the decoder as the first place to look in Gate 3.

Also relevant to later method configuration: at ε = 0.99, trunk occupancy is high (median about
0.75–0.80, `fc2` up to 0.91). A GPM run using ε = 0.99 would leave the trunk little room after one
task, and less after two or three with accumulation. Choose GPM's ε deliberately. Do not inherit 0.99
from the sweep.

## 6. Padded chunk positions and the reachability probe

The action mask acts **only in the loss**. `SelfAttention` calls `F.scaled_dot_product_attention`
with no attention mask (`flowcl/models/trunk.py:44`). A padded position can therefore still receive
an output gradient `δ = ∂L/∂z ≠ 0` wherever a later operation mixes tokens. Its input then enters
`∇W = δ xᵀ`, and belongs in the basis.

For each checkpoint, one diagnostic forward/backward pass tested this directly on the **module
output** gradient. The input gradient `Wᵀδ` would be the wrong test, because it vanishes whenever `W`
does. There was no optimizer step, and `.grad` was restored afterwards.

| Decoder layer (L = 4 blocks) | Padded rows reachable? | Primary basis |
|---|---|---|
| `action_in` | yes | all tokens |
| blocks 0–2, every layer | yes | all tokens |
| block 3 self-attn K, V | yes | all tokens |
| block 3 self-attn Q, out_proj; cross-attn Q, out_proj; MLP fc1, fc2 | **no** | valid tokens |
| `action_out` | **no** | valid tokens |

27 of the 34 action-position layers are reachable. On all five checkpoints, the measured rule
matches the hand-derived rule exactly (`reachability_mismatches = []`). Trunk layers and
cross-attn K/V have no action positions; they use one basis over all tokens.

Robustness: the largest |ρ_valid − ρ_all| at ε = 0.95 is 0.002 (`blocks.{1,2}.cross_attn.out_proj`).
No layer changes saturation class (`classification_changes.valid_vs_all = []`). With H = 16 and
`tokens_per_sample = 16`, every valid action position was kept.

| Batch / workers | 64 / 4 |
| Probe batch | 32 (half with padded chunks, half without) |

Measurement choices:

- **Stats:** the checkpoint's own frozen stats, never refitted (§3.3). The verdict checkpoint uses
  `9076ed62…`, the same Task-1 stats as Gate 1.
- **Forward:** `policy.eval()`, `torch.no_grad()`, fp32 with no autocast.
- **`s` and noise:** `s` from the policy's training sampler (uniform), `A_0 ~ N(0, I)`, both from a
  CPU generator seeded with `derive_seed("gate2_capture::<run_id>", task_key, 0)`. The probe uses a
  `gate2_probe::` tag.
- **Activations are uncentered** (the GPM convention: `∇W = δ xᵀ` lies in the span of the raw inputs).
- **SVD by streamed Gram:** `K_l = Σ x xᵀ` in float64, then `eigh`, sorted descending, with small
  negative eigenvalues clamped. This gives the same `U` and `σ²` as `svd(R_l)`, and a test pins that.
- **Token-type counts, trunk layers:** context_query 14.0%, state 0.4%, language 14.3%, vision 71.3%
  of 94 112 kept tokens. This matches the 32 / 1 / 32 / 164 layout of the 229-token sequence.

No GPM incremental accumulation was used; T1 needs none. It arrives with `gpm` in build step 8.
