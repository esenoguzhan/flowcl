## 1. What this gate answers

Spec §10.3 Gate 1:

> Does forgetting exist?  
> **Forgetting ≥ 15 pp on at least one sequence, else change the curriculum.**

The spec writes this as `F_1 ≥ 15 pp`. Read literally that is ambiguous: §8.2
defines `F_1` as *final average success*, and a 15% final average would be a
catastrophically bad policy rather than evidence of forgetting. The quantity the
gate is about is the forgetting *gap*. `flowcl/analysis/gates.py:gate1` therefore
judges **NBT** (negative backward transfer), and the docstring records the
reading. The deviation is noted here as §11 requires.

Two forgetting columns are reported because they can disagree, and the
disagreement is informative (`flowcl/experiments/gate1.py`):

* **NBT** — drop from each task's own just-after-training performance
  (`R[j][j] − R[T][j]`), averaged over the tasks that *can* be forgotten (the
  last task is excluded; including it would dilute NBT by `1/T` as a function of
  curriculum length). This is what Gate 1 is judged on.
* **Gap to the §10.4 single-task references** — how far the *final* sequential
  policy is from independently trained policies. Larger than NBT when the
  sequential run never learned a task well in the first place, which would be a
  Gate 0 problem masquerading as forgetting.

“At least one sequence” is the right quantifier: the gate asks whether the
*benchmark* can exhibit forgetting at all. One sequence that does is enough to
proceed. Only `seq_hetero` was run.

## 7. How to read the zeros

Percentile bootstrap on 0/50 is the degenerate interval `[0.0, 0.0]`. That is
“no successes in 50 rollouts,” not a proof that residual success is exactly
zero. A rule-of-3 95% upper bound is about \(3/50 = 6\%\). The forgetting claim
does not depend on that distinction: even if every forgotten cell were 6%, NBT
would still be ~83 pp, well above 15.

The same caveat applies in reverse to Goal's `[100.0, 100.0]`: 50/50, not a
broken success predicate. Horizons vary (103–586); none are near-zero.

## 8. Diagonal vs Gate 0: the Object 78% cell

Three of four just-after-training numbers match the independent single-task
ceilings (CIs overlap). **Object does not:** 78.0 [66.0, 88.0] after sequential
Spatial→Object vs 92.0 [84.0, 98.0] trained from scratch.

That 14 pp is *not* forgetting. NBT for Object is 78 pp (it reached 78 and then
went to 0). The extra 14 pp in the single-task gap is “never reached the Gate 0
ceiling in the sequential run.” Candidate causes, in the order the artifacts
support them:

1. **Frozen Task-1 stats.** Object is trained under Spatial state normalisation
   (§6.4). Gate 0 Object fitted its own stats (`50eaaa9bb2ac8c9375dc8397c48fef2a`).
2. **Warm-start from Spatial weights** rather than a fresh init.
3. **Unpaired eval seeds** (§6.3). The CIs overlap in [84.0, 88.0], so this drop
   is **not** significant at 95% on unpaired intervals.

Do not treat Object's 78% diagonal as a Gate 0 failure of the architecture.
Treat it as a possible sequential-protocol cost. Goal still hits 100% two stages
later under the same frozen Spatial stats, so stats alone do not make later
tasks unlearnable. Object's CI [66.0, 88.0] *does* straddle Gate 0's 80%
threshold; that is a property of this sequential cell, not a reason to reopen
Gate 0.

measurements, not missing features.

1. **One seed.** Seed 0 only. The Stage A matrix needs 3 seeds. Gate 1's
   question (“does forgetting exist?”) is answered; variance across seeds is not.
2. **Only `seq_hetero`.** No reverse order. No `seq_correlated`. The language

   Interference is inferred from the matrix, not measured. `seq_hetero`'s
   expectation that this is “the regime where hard projection (GPM) should be
   viable” is confirmed only for the forgetting half; \(c_l\) is still
   unmeasured.
4. **FWT not written** into `result.json` `metrics`. The number in §3 is
   derived from the matrix and Gate 0, not loaded from the artifact.
5. **No videos.** `record_video: false`. Qualitative figures will need a later
   eval with video on, on the same checkpoint and the same `episode_idx` set.
6. **Not hardware.** Stage B (AgileX) is out of scope until Stage A methods are
   chosen.
7. **Object diagonal unpaired vs Gate 0.** Do not quote “sequential training
   costs 14 pp on Object” as a significant result.
