## 1. What this gate answers

Spec §9 / §10.3 Gate 0:

> Is single-task success adequate?  
> **≥ 80% on each chosen LIBERO task, else fix the policy before anything else.**

The §4.1 encoder escape hatch is a *different* threshold (~70%). It is a one-time
budget: swap to a from-scratch ResNet-18 only if frozen features cannot learn the
tasks. The 70–80% band is a training-recipe problem, not an encoder problem.

Gate 0 trains an **independent** policy per task. A jointly trained policy would
answer a different question and could hide a task the architecture cannot fit.

These four policies are also the §10.4 single-task references that later FWT / gap
columns will use. Do not delete the run directories.

## 5. Protocol (do not silently change later)

### 5.1 Tasks and why they were chosen

From `configs/curriculum/seq_hetero.yaml`. Consecutive tasks share neither scene,
object set, nor motion primitive.

| Order | Suite | Instruction (task name) | Design rationale in the curriculum YAML |
|---|---|---|---|
| 1 | SPATIAL | pick up the black bowl from table center and place it on the plate | Least spatially-qualified spatial task, so Gate 0 is not bottlenecked by fine spatial-reference discrimination |
| 2 | OBJECT | pick up the milk and place it in the basket | Large, visually distinctive object |
| 3 | GOAL | open the middle drawer of the cabinet | Articulated-object motion; shares no primitive with the pick-and-place tasks |
| 4 | LONG (`libero_10`) | turn on the stove and put the moka pot on it | Two-stage long-horizon kitchen task |

`seq_hetero_reverse` uses the same four tasks in reverse and **was not run**. It is
a different experiment: §3.3 fits frozen normalisation on Task 1, which would then
be the long-horizon task rather than the spatial one.

`seq_correlated` (milk / tomato sauce / cream cheese / BBQ sauce) **was not run**.

### 5.2 Policy

`flowpolicy_base` (`configs/policy/flowpolicy_base.yaml`):

| Field | Value |
|---|---|
| Vision | frozen DINOv2-S (`facebook/dinov2-small`, width 384), trainable linear patch projection |
| Language | frozen CLIP-B text tower (`openai/clip-vit-base-patch32`); **per-token** embeddings, not a pooled sentence vector (documented deviation from a naive §4.1 reading; needed so `seq_correlated` object nouns are distinguishable) |
| Both encoders | `pretrained: true`; vision and text towers frozen for the whole run (§0) |
| Trunk | 8 layers, `d_model` 512, 8 heads, MLP ratio 4.0, 32 context tokens |
| Decoder | 4 flow-matching blocks (not 6: six would be ~66.9M trainable, above the 20–60M band). Config comment: **~53.8M trainable** |
| `s` sampler | uniform on `[0, 1]` |
| Inference ODE | Euler, `N = 10` steps |
| Action chunk | `H = 16` |
| Execution | first `k = 8` actions open-loop, then replan; **no temporal ensembling** |

### 5.3 Training recipe (identical for all four policies)

From each run's `config.yaml`:

| Field | Value |
|---|---|
| Steps | 30 000 |
| Batch size | 64 |
| Learning rate | `1e-4` |
| Weight decay | `1e-4` |
| Grad clip | 1.0 |
| Warmup | 100 steps |
| AMP | true |
| Accumulation | 1 |
| Workers | 4 |
| Device | `cuda` |
| Demos | 50 / task (all shipped demos; §3.2) |
| Role | `single_task_reference` |

Loss is masked conditional flow matching:
`|| v_θ(A_s, o, s) − (A_1 − A_0) ||²` with `A_s = (1−s)A_0 + s A_1`.

### 5.4 Evaluation protocol (§8.1)

From `configs/eval/libero_eval.yaml` and `flowcl/envs/libero_env.py`:

- 50 rollouts per task, one per LIBERO `init_files` state, **not** randomly sampled extras.
- Success = `env.check_success()` (LIBERO's own predicate). Episode stops at first success.
- Hard cap 600 env steps = 30 s at 20 Hz OSC.
- Images 128×128, cameras `agentview` + `robot0_eye_in_hand`.
- Rollout seed = `derive_seed(run_id, task_key, episode_idx)` (BLAKE2b; no method argument).
- Policy sampler uses a **CPU** `torch.Generator` seeded with that value, then tensors are moved to CUDA. This keeps `s` / `A_0` streams device-independent.
- Bootstrap: 10 000 resamples, confidence 0.95, seed 0.

## 10. What this run does *not* show

Write these as limitations, not as future-work padding: they are missing
measurements, not missing features.

1. **One seed.** Seed 0 only. The Stage A matrix needs 3 seeds. Gate 0's question
   (“can the architecture learn these tasks?”) is answered; variance across seeds
   is not.
2. **No `seq_correlated` coverage.** Tomato sauce, cream cheese, and BBQ sauce
   have no single-task reference. `results/gate0/language_check.json` does not
   exist. §5 says every conclusion from that curriculum assumes the policy uses
   the instruction. Until the language check passes, do not report correlated-
   sequence forgetting as a CL result.
3. **No reverse order.** `seq_hetero_reverse` changes which task owns the frozen
   stats. Not interchangeable with this run.
4. **No forgetting measurement.** These are four isolated policies, not a
   sequential learner. `F_1`, NBT, FWT are undefined here.
5. **No subspace / interference numbers.** `ρ_l` and `c_l` were not computed.
6. **No videos.** `record_video: false`. Qualitative figures will need a later
   eval with video on, on the same checkpoint and the same `episode_idx` set.
7. **Not hardware.** Stage B (AgileX) is out of scope until Stage A methods are
   chosen.
