## 1. Protocol

- **The policy:** the same as T5's Gate 0, an independent single-task `flowpolicy_base` with
  frozen DINOv2-S. It trains every parameter, 30k steps at lr 1e-4, batch 64, AMP, seed 0, on all
  50 demos.
- **The evaluation:** 50 rollouts, with a 600-step limit.
- **The decision:** Gate 0's registered point-estimate rule. A CI that straddles 80% is flagged
  `borderline`, but the point estimate decides.

**The queue** (`scripts/queue_gate0_t8.sh`):
- **Before each slot:** it refuses the slot if its run directory or report already exists. None
  did.
- **The backup rule:** the backup runs only if this invocation's primary step returned 0 and its
  report was written after the step started, covers exactly the primary task, and says
  `passed: false`.
- **Both backups ran under this rule.**

The rule gives no automatic third choice, and the options change the curriculum or the protocol,
so this is the user's and the supervisor's call (D1, W1). In each case the replacement is
registered before its Gate 0 runs.

|---|---|---|
| **a. New pre-registered candidates from other suites** | Unused LIBERO-Goal, LIBERO-Object or LIBERO-Spatial tasks. | **b. The one unused LIBERO-10 task** | `LIVING_ROOM_SCENE2_put_both_the_cream_cheese_box_and_the_butter_in_the_basket`. | It covers only one slot, and it is another two-object living-room basket task, the family that failed three times here. |

| **d. Accept the borderline primaries** (T6 72, T8 68) | Lower the threshold for these slots. | Not recommended: it breaks the registered rule after the outcome is known, and low diagonals would weaken the plasticity measure. |

**Recommendation:** register option (a), or (a) and (b), now, with a ranked list and its own
backups, and run its Gate 0 in the next queue. Keep (c) as the fallback if those fail too. The
choice of suites (revisit or new scene) is the substantive question for D1.
